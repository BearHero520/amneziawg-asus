# 核心更新与恢复

从插件 0.5.0 开始，ARM64 与 ARMv7 各有完整安装包和独立核心资源。0.4.x 需要先离线安装完整 0.5.0 包，才能使用更新页；完整安装会停止服务，之后手动启动。

“核心版本”是本项目适配版本，例如 0.5.0；上游协议引擎仍为 README 固定的版本。界面版本和核心版本分别显示。核心包含 ASUS 管理代码，不能用上游原版二进制直接覆盖。

## 使用

1. 打开“核心更新”，点击“检查更新”。请求由路由器访问本项目的 `updates/preview.json`，只读取版本元数据。
2. 有较新兼容版本时，点击“手动升级”，阅读断线提示并勾选后确认。无新版本时按钮不可用。
3. 下载及候选核心检查期间服务继续运行。切换阶段会停止原先运行的服务、替换核心并启动这些服务；没有运行的服务保持关闭。
4. 如果管理页面通过此 VPN 连接，可能暂时失联；等待客户端重新连接，再查看更新状态。网页请求超时不代表后台任务停止，不要重复提交。
5. 成功切换后可用“回滚到备份”。手动回滚无需联网，保留切换前的核心作为下一次可撤销备份。

完整插件离线安装会清除旧核心备份与历史更新元数据；私密配置保留。核心更新本身不清除配置、Peer、密钥或开机启动选项。

## 校验与空间

- 更新源固定为本仓库，核心 URL 必须对应明确的发布版本和架构；仅允许 GitHub 所需 HTTPS 下载跳转，使用系统 CA 验证证书。
- 校验文件大小、SHA256、ELF 架构、可执行探测、适配接口 ABI 和兼容系列。更新信息有效期一小时，服务端再次核对用户确认的版本。
- SHA256 清单通过同一受信任的 GitHub HTTPS 来源获取，不是独立发布者签名。
- 核心最大 32 MB；先检查 JFFS 可用空间，要求新核心大小加 2 MB 余量。0.5.0 核心原始大小约 6.6–6.9 MiB。
- 使用同一文件系统中的硬链接保留旧核心、原子重命名激活候选核心；不支持硬链接时在停服务前取消。已有备份会占空间，磁盘空间不足时应使用完整离线包或先合理清理无关文件，不要手工删除正在使用的备份。
- 不支持原始核心自动追新、任意镜像地址或强行跨架构/跨接口系列升级。新插件系列需完整离线安装。

## 失败处理

- 下载、校验、执行探测或空间检查失败：当前核心及服务不变。
- 激活或恢复新核心服务失败：尝试清理新服务、恢复旧核心，并恢复原先运行的服务。客户端已有断线保护规则不主动解除。
- 停止、清理、文件恢复或旧服务启动也失败：显示“需要恢复”，保留备份和事务标记，阻止其他变更。此时不能保证 VPN 自动恢复，需通过家庭 LAN 或其他管理通道排查。
- 更新中进程意外退出：后台可能保留忙碌标记。重启路由器后，启动脚本优先调用旧核心进行校验恢复；仅在确认是另一次系统启动时执行。之后按配置中的开机启动选择启动服务。未启用开机启动的服务需手动启动。
- `/koolshare/bin/amneziawg-go.previous` 是备份，`/koolshare/amneziawg/update-state.json` 是进度元数据，`update-busy` / `update-pending` 是事务标记。不要在更新中手工删除这些文件。

启动检查确认的是本地控制接口和网络规则成功，不等于远端握手、DNS、网站或第三方代理已正常。更新后仍需外网设备验证。断电恢复目前通过隔离文件系统模拟验证，尚未进行真实路由器断电测试。

## 发布流程

运行 `build.ps1`，生成两个离线包、两个核心资源、`amneziawg-core_VERSION.json`、`SHA256SUMS.txt` 和 `updates/preview.json`。先以草稿 Release 上传并校验所有资源，再公开 Release，最后更新 main 上的清单，避免检查更新指向尚不可用的资源。保持已发布版本的资源不可变；任何核心修改都使用新版本号。构建版本、安装器版本、界面资源版本和打包版本需同步更新。
